Assignment: Develop an AI-Powered Product Assistant Chatbot
1. Objective
Your task is to design and develop an AI-powered Product Assistant Chatbot that helps users understand and use a product.
The chatbot should be able to answer questions related to the product by using product documentation as its knowledge source. The solution must use a Retrieval-Augmented Generation (RAG) architecture and should also support conversation memory.
The goal of this assignment is to build an end-to-end chatbot application that can:
Answer questions about the product.
Explain product features and functionalities.
Guide users on how to use the product.
Explain the technologies used to develop the product.
Provide information about the product architecture and workflow.
Remember previous conversations within a user session.
Store conversation history in a database.

3. RAG Implementation
Develop a RAG-based chatbot using the Product Knowledge Document.
The system should perform the following steps:
Load the PDF/DOCX document.
Extract the text from the document.
Split the document into smaller chunks.
Generate embeddings for each chunk.
Store embeddings in a vector database.
Convert the user's question into an embedding.
Retrieve the most relevant document chunks.
Provide the retrieved context to the LLM.
Generate a response based on the retrieved information.
RAG Flow
User Query
↓
Generate Query Embedding
↓
Vector Database Search
↓
Retrieve Relevant Document Chunks
↓
Send Context + User Query to LLM
↓
Generate Final Response
The chatbot should answer product-related questions primarily using the information available in the product documentation.
4. Conversation Memory Implementation
The chatbot should also implement conversation memory.
The purpose of memory is to allow the chatbot to understand previous messages from the user during the conversation.
For example:
User:
What technologies are used in this product?
Chatbot:
This product uses Python, FastAPI, LangChain, and MongoDB.
User:
Why did we use it?
The chatbot should understand that "it" refers to the technologies discussed in the previous conversation.
5. Conversation Storage
All user conversations should be stored in a database.
Each conversation should contain information such as:
User ID
Session ID
User Query
Assistant Response
Timestamp
Example conversation structure:
{
    "user_id": "user_123",
    "session_id": "session_456",
    "conversation": [
        {
            "role": "user",
            "message": "What is the purpose of this product?",
            "timestamp": "2026-08-28T10:30:00Z"
        },
        {
            "role": "assistant",
            "message": "This product helps users...",
            "timestamp": "2026-08-28T10:30:05Z"
        }
    ]
}
Alternatively, conversations can be stored as individual records:
{
    "user_id": "user_123",
    "session_id": "session_456",
    "user_query": "What is the purpose of this product?",
    "assistant_response": "This product helps users...",
    "created_at": "2026-08-28T10:30:00Z"
}
6. Memory Flow
The chatbot should follow this workflow:
User Sends Query
↓
Retrieve Previous Conversation History Using User ID and Session ID
↓
Retrieve Relevant Product Information Using RAG
↓
Combine:
System Instructions
Conversation History
Retrieved RAG Context
Current User Query
↓
Send Combined Context to LLM
↓
Generate Response
↓
Return Response to User
↓
Store User Query and Assistant Response in Database
7. User and Session Management
The application must support multiple users and sessions.
Each user should have a unique:
user_id
Each conversation session should have a unique:
session_id
Example:
User A
 ├── Session 1
 │    ├── Conversation 1
 │    ├── Conversation 2
 │    └── Conversation 3
 │
 └── Session 2
      ├── Conversation 1
      └── Conversation 2
The chatbot should only retrieve the conversation history related to the current:
User ID
Session ID
This ensures that conversations from different users or sessions are not mixed.
